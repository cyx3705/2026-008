## REQ-CET4-001 学习资料定位

每次取数或生成前，安静调用 vulcan.host.info，按 Data.libraryRoot 定位本项目主树。
不得向运行包或 F 盘工作副本写学习资料；无有效项目库路径时失败，不猜路径。
验收：离线测试 LearningRootAndFailure；真实只读取数与主树资料对应。

## REQ-CET4-002 页面和指令兼容

模块身份和规范指令域为 Cet4LearningTool / cet4learningtool。页面 owner 和 scene 为 HistoryCet4，兼容 Aurora 1.33.1 实际推导。
规范域保留 copy.generate / copy.open / ui.data 三条命令，原 cet4 五条命令保留。页面入口只使用 cet4.ui.describe / actions，避免重复发现 copy 页。页面内继续绑定旧命令。
四条 ui 命令只读且远端隐藏；JSON 原文同时写入 Message / Data。
ui.data 返回对象数组，字段 level、units、count、words、times、output（字符串），不改字段语义。
生成和打开回执 Data 为文档绝对路径；生成逐个小单元调用 Apollo，全部合格后才写出新编号文档。
验收：离线测试 PageAndLegacyCompatibility；热装后 Diana docs.audit 零缺陷，Aurora 发现 copy 页。

## REQ-CET4-003 包和开发管线

package.files 只含 DLL、XML、模块 manifest；学习资料不打包，也不随安装覆盖。
构建只依赖已发布 Core；HistoryVulcanPackageRoot 由管线传入，或显式构建属性提供。
本地 Directory.Build.user.props 可配置路径，但必须忽略且不提交。
验收：离线测试 PackageIdentity，submit 的 nupkg 装载回执。

此次验证不调用真实 AI、不打开 Word、不生成真实学习文档；AI 生成的实际内容质量不属于本次容器升级验收。
